## Lore design (decided session 2; **session 12 changes are in `claude/lore-design.md`**: the graph holds only pinned entries, the Codex lists all)
- Nodes have **tags**, not a single type. Six generic tags ship (Character, Event, Place, Faction, Item, Note); users add their own. A node can have several tags. Each tag has its own color.
- **Tag colors**: the user can pick ANY color for any tag, and can edit/extend the color palette with new colors (no fixed cap, no forced repeat). New tags default to the next palette color.
- On the graph a node has a neutral body with a ring split into one segment per tag color (or small dots).
- Every subject is its own entry/node.
- **Strong link**: user-drawn, visible string between two nodes, optional label, undirected.
- **Weak link**: a reference bubble near a node, unlabeled, can point to any node (book or user). Added when creating/editing a node via suggestions (plain name/text match against existing nodes' names) or user search.
- Book entries in `lore.json` carry only weak links (explicit text mentions). Strong links are only ever drawn by the user.
- Pinned book nodes: book text read-only; the user can add links, extra tags and a private note (stored separately from book data).
- Lore is stored **per character**, inside the character, so character export/import carries it. A separate lore-only export/import is also wanted.
- Timeline view deferred (YAGNI); no date field in the schema for now (adding an optional one later is backward compatible).
- Lore search is lore-only: "In my lore" / "In the rulebook". Play widgets will get Lore items when the Lore tab exists.

## Technical decisions (Step 2 grill-me, approved session 2)
- **State management**: Riverpod (flutter_riverpod 2.x, plain providers).
- **Storage**: no database. One JSON file per character in the app documents directory (`characters/<id>.json`). A character is one self-contained document. Export/import = copy the file. **Session 5**: `settings.json` next to it remembers the selected character id; `charactersProvider` (`CharactersNotifier`: add / select / save / delete) is the one place that changes characters. **Session 6**: shared libraries (custom backgrounds, custom spells) are plain JSON lists handled by the generic `JsonListStorage<T>`. **Session 11**: glossary notes use it too (`glossary_notes.json`).
- **Models**: `json_serializable` (needs build_runner; generated `.g.dart` files are never hand-edited, not committed).
- **Folders**: feature-first, shallow: `lib/rules/` (loader + rules models), `lib/character/` (model, storage, derived stats, equipment rules, magic rules, level-up rules, play layout, play items, damage roll, providers), `lib/features/<create|characters|play|roll|sheet|spells|level_up|glossary|lore>/`, `lib/shared/` (theme, app shell, device class, small widgets), `lib/l10n/`.
- **Rules data**: ALL rules converted to JSON (done). Bundled as assets in `assets/rules/`, loaded once at startup. Typed Dart models are added only when a feature needs them (YAGNI): so far classes, backgrounds, talents, specializations, spells, weapons / armor / shields / catalog, magic (armor strain, stunts, mishaps), stunt lists (combat, exploration, roleplaying), the default Play widgets and layouts, (session 11) the glossary terms and (session 12) the lore entries and tags.
- **Progression**: Character stores current state only. Derived values are pure functions. **Session 7**: no level-up log, but the character keeps `owedGains` (skipped gains) and one `levelUpUndo` snapshot of the level-up fields. Specializations carry their class `slot` (6 or 14).
- **Play widgets and layouts (session 9)**: inside the character JSON. `playWidgets` (`List<PlayWidgetData>?`, null = defaults not copied yet; shared by all devices) and `playLayouts` (device class -> `List<PlayTile {widget, x, y, width, height}>`). A widget without own place uses the default place from `default_layouts.json`, else goes to the bottom. `Character.notes` was removed.
- **Versioning**: none for now (YAGNI). Revisit before the first real release.
- **i18n**: Flutter gen-l10n with ARB files (lib/l10n/app_en.arb). Default widget titles live in `default_layouts.json` (English); glossary terms live in `glossary.json` (English).
- **Testing**: unit tests only (loader, models, derived stats, storage, equipment, magic, level-up, play layout / play items / damage roll, glossary). Widget/golden tests later if needed.
- **JSON defaults**: list/map fields of models get their default from `@JsonKey(defaultValue: ...)` only and are `required` in the constructor (json_serializable warns when both constructor and JsonKey give a collection default). Scalars (level, xp, mana, equipped...) keep both, no warning. Callers of `Character(...)` must pass every list/map explicitly (including `owedGains` and `playLayouts`; `playWidgets` is optional).
- **Build**: `python build.py` (flags `-g` gen-l10n, `-b` build_runner, `-t` tests, `-win` run on Windows, `-a` Android). See README.md.

## Rules data files (assets/rules/ on the user's computer; copies in the Project under rules/data/)
All ids are lowercase kebab-case (`light-blades`, `winters-grasp`); `slug()` in lib/rules/slug.dart reproduces them from names. Costs are stored in copper (`costCp`).
- `classes.json` (XP table, advancement cost, 3 classes x 20 levels with `gains` / `specialization` / `powers`, starting gear, Defense, Speed; per class `startingArmor`, `startingWeapons`, mage `startingExtraItem`; **session 7**: `focusChoices` on warrior level 2)
- `backgrounds.json` (30 backgrounds, 2d6 tables, 3d6 ability score table, racial traits). The book heading says 29, the list has 30.
- `talents.json` (33 talents incl. optional Spell Expertise; structured requirements)
- `specializations.json` (21 specializations + Grey Wardens), `gear.json` (armor, shields, weapons, ~220 items), `poisons.json` (poisons, grenades, traps), `magic.json` (mana, casting, stunts, mishaps, `armorStrain`; typed since session 6), `exploration.json` (exploration/roleplaying stunts, goals, organizations; stunts typed in session 8), `core.json` (tests, combat stunts (typed in session 8), actions, attack modifiers, all 80 focuses; weapon focuses carry `weaponGroup`), `lore.json`, `abilities.json`, `starter_spells.json`, `spells.json` (108 spells, plain list; ids derived from names; each spell has `requires` = structured requirements `{type: spell|talent|specialization, id, degree?}` next to the display text `requirement`).
- **Session 9**: `default_layouts.json` = `{templates: [{id, title, style, items}], layouts: {phone, tablet, desktop: [{widget, x, y, width, height}]}}` (not rules, but loaded with them). Item ref `"*"` = all of that type the character has.
- **Session 11**: `glossary.json` = plain list `{topic, name, text, aliases?, autoLink?, extra?}` (79 paraphrased terms; not a copy of book text). Needs a spot-check against the book.
- Naming fix: the class text says "Throwing Weapon Style", the talent list says "Thrown Weapon Style"; ids use `thrown-weapon-style`.
- The generation scripts are scratch files and are not kept; the JSON files are the source of truth now.
